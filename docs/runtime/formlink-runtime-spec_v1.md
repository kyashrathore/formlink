**Audience**: LLM Codegen Agents & Human Developers
**Purpose**: This is the single source of truth for the Formlink runtime. It serves as both a technical specification and an instruction manual for generating code. Adhere strictly to these rules.

## 0. Quickstart

Install (pnpm only)

- pnpm add @formlink/runtime @formlink/ui motion react react-dom

CSS (Next.js App Router)

- In `app/layout.tsx` import the UI CSS once:
  - import '@formlink/ui/globals.css'

Tailwind content (v4)

- Ensure Tailwind scans the UI package so styles are not purged. In your Tailwind config:
  - content: [
    './src/**/*.{ts,tsx}',
    'node_modules/@formlink/ui/dist/**/*',
    'node_modules/@formlink/ui/ui/**/*'
    ]

Client components

- Components that render the runtime or UI must be client components:
  - Add 'use client' at the top of files that call `createRuntime` or render inputs/Devtools.

Create a runtime (default transport)

- Use the built‑in Formfiller‑compatible transport by passing `formfiller`:

```tsx
'use client'
import { createRuntime } from '@formlink/runtime'
import { Devtools } from '@formlink/runtime/devtools'
import type { Form } from '@formlink/schema'

const form: Form = /* your schema */

const runtime = createRuntime({
  form,
  formfiller: {
    formId: 'your-form-id',
    submissionId: 'uuid-or-random',
    formVersionId: 'v1',
    baseUrl: '', // defaults to ''
    isTestSubmission: false,
  },
  uiMode: 'classic',
})

// Optional: Devtools (dock left so the page remains visible)
;<Devtools runtime={runtime} mode="dock-left" dockWidth={360} />
```

````
## 1. Core Concepts

1.  **Architecture**: A **headless runtime** (`@formlink/runtime`) manages all state and logic. UI components (`@formlink/ui`) are presentational and render the state provided by the runtime.
2.  **Single Source of Truth**: The runtime is the **only** source of truth for form state. Your generated UI code must **never** use `useState` or other hooks to manage form data.
3.  **Packages**:
    - `@formlink/runtime`: The headless logic engine.
    - `@formlink/ui`: A library of components, distributed via a `shadcn/ui`-style registry.
    - `@formlink/chat`: A specialized adapter for conversational forms.

## 2. Form Schema Contract

This section defines the JSON structure for a form, which is generated by a separate AI based on a user prompt. Your goal is to generate a UI that correctly interprets this schema.

### Top-Level `Form` Object

- `id`: `string` - Unique identifier for the form.
- `title`: `string` - The main title of the form.
- `description`: `string` (optional) - A subtitle or description.
- `questions`: `Question[]` - An array of question objects.
- `settings`: `object` (optional) - Contains settings for the form.

### `Question` Object

- `id`: `string` - A unique identifier for the question (e.g., `q1_full_name`).
- `title`: `string` - The main text of the question/label.
- `description`: `string` (optional) - Additional help text.
- `validations`: `object` (optional) - A map of validation rules (e.g., `{ "required": { "value": true } }`).
- `type`: `object` - **This is a discriminated union.** The `name` property determines the question type and the other properties available within the `type` object.

### Question Types (Discriminated by `type.name`)

- `name: 'text'`
  - `format`: `string` - e.g., `"text"`, `"textarea"`, `"email"`, `"url"`, `"number"`.
- `name: 'singleChoice' | 'multipleChoice'`
  - `display`: `string` - e.g., `"radio"`, `"dropdown"`, `"checkbox"`.
  - `options`: `Array<{ value: string, label: string, score: number }>`.
- `name: 'rating'`
  - `config`: `{ min: number, max: number, step: number, minLabel?: string, maxLabel?: string }`.
- `name: 'linearScale'`
  - `config`: `{ start: number, end: number, step: number, startLabel?: string, endLabel?: string }`.
- `name: 'likertScale'`
  - `options`: `string[]` - An array of labels (e.g., `["Strongly Disagree", ..., "Strongly Agree"]`).
- `name: 'ranking'`
  - `options`: `Array<{ value: string, label: string, score: number }>`.
- `name: 'date'`
  - `format`: `string` - e.g., `"date"`, `"dateRange"`.
- `name: 'fileUpload'`, `name: 'address'`, `name: 'signature'`: These types have no additional properties within the `type` object.

### `settings` Object

- `branching`: `{ enabled: boolean }` - Must be true to enable branching.
- `journeyScript`: `string` - An **XML string** (not JavaScript) that describes the high-level branching logic for the backend to interpret. The client runtime reads the _result_ of this logic in `context.visibleIds`.

### Schema-to-Validator Translation (Internal Runtime Process)

The runtime internally translates the declarative `FormSchema` into an executable `zod` validation schema that is then used by TanStack Form. This process happens automatically within `createRuntime`.

1.  **Iteration**: The runtime iterates through the `form.questions` array.
2.  **Dynamic Zod Chain Construction**: For each `question`, it constructs a `zod` validator chain by mapping the schema rules to Zod methods.
    - `validations.required: true` -> `.min(1, "...")` or `.nonempty()`
    - `type.format: 'email'` -> `.email()`
    - `validations.minLength` -> `.min()`
    - `validations.pattern` -> `.regex()`
3.  **Assembly**: It assembles these individual validators into a single `z.object({...})`, where keys are the question `id`s.

This architecture allows the `FormSchema` to remain simple and AI-friendly, while the runtime handles the complex task of creating the executable validation logic.

## 3. Runtime API (`@formlink/runtime`)

### Initialization

```tsx
import { createRuntime, fetchTransport } from "@formlink/runtime";
import { form } from "./schema";

const rt = createRuntime({
  form,
  transport: fetchTransport({ baseUrl: "/api" }),
});
````

Default Transport (Formfiller‑compatible)

Many apps use the following API routes:

- Upload: `POST /api/upload` (multipart)
- Save answers: `POST /api/forms/:formId/save-answers` (JSON)
  - Partial saves are the same route with a different body shape

You can adapt the runtime transport to these endpoints with a small wrapper.

```tsx
import type {
  RuntimeTransport,
  RuntimeSubmissionResult,
  RuntimeValues,
} from "@formlink/runtime";

type FormfillerTransportOpts = {
  baseUrl?: string; // default ''
  formId: string;
  submissionId: string;
  formVersionId: string;
  isTestSubmission?: boolean;
};

export function createFormfillerTransport(
  opts: FormfillerTransportOpts,
): RuntimeTransport {
  const {
    baseUrl = "",
    formId,
    submissionId,
    formVersionId,
    isTestSubmission = false,
  } = opts;
  const saveUrl = `${baseUrl}/api/forms/${formId}/save-answers`;
  const uploadUrl = `${baseUrl}/api/upload`;

  return {
    async submit(values: RuntimeValues): Promise<RuntimeSubmissionResult> {
      const body = {
        submissionId,
        formVersionId,
        submissionStatus: "completed" as const,
        testmode: isTestSubmission,
        allResponses: values,
      };
      const res = await fetch(saveUrl, {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify(body),
      });
      if (!res.ok) throw new Error(`Submit failed: ${res.status}`);
      const payload = await res.json().catch(() => undefined);
      return { response: payload };
    },
    async savePartial(values: RuntimeValues): Promise<void> {
      const entries = Object.entries(values);
      const [questionId, answerValue] = entries[entries.length - 1] ?? [];
      const body = {
        submissionId,
        formVersionId,
        isPartial: true,
        questionId,
        answerValue,
        submissionStatus: "in_progress" as const,
        testmode: isTestSubmission,
      };
      const res = await fetch(saveUrl, {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify(body),
      });
      if (!res.ok) throw new Error(`Partial save failed: ${res.status}`);
    },
    async upload(questionId: string, file: File | Blob) {
      const fd = new FormData();
      fd.append("questionId", questionId);
      fd.append("formId", formId);
      fd.append("submissionId", submissionId);
      if (file instanceof File) fd.append("file", file);
      else fd.append("file", file, questionId);
      const res = await fetch(uploadUrl, { method: "POST", body: fd });
      if (!res.ok) throw new Error(`Upload failed: ${res.status}`);
      const payload = await res.json();
      // Expect: { url: string, name: string, size: number, mimeType?: string }
      return payload;
    },
  };
}

// Usage
// const rt = createRuntime({ form, transport: createFormfillerTransport({ formId, submissionId, formVersionId }), uiMode: 'classic' })
```

### Reading State (`context`)

- `context.status`: The overall state of the form: `'idle' | 'filling' | 'submitting' | 'completed' | 'error'`.
- `context.currentId`: The ID of the current question (for Typeform-like flows).
- `context.visibleIds`: An array of all currently visible question IDs (for Classic flows).
- `context.progress`: An object `{ index, total, percent }`.
- `context.get.q(qId)`: Returns the question object.
- `context.get.value(qId)`: Returns the question's current answer.
- `context.get.error(qId)`: Returns the first validation error for a question.

### Changing State (`actions`)

- `actions.start()`: Begins the form, changing `status` from `'idle'` to `'filling'`.
- `actions.set(qId, value)`: Sets an answer.
- `actions.validate(qId)` / `actions.validateAll()`: Trigger validation.
- `actions.next()` / `actions.prev()` / `actions.goTo(qId)`: Handle navigation.
- `actions.submit()`: Submits the form. Manages the `'submitting'` and `'completed'` statuses.
- `actions.reset()`: Resets the form and returns `status` to `'idle'`.

## 4. UI Generation Rules & Patterns

### Overall Structure: The Status Machine

Your top-level component **MUST** use `context.status` to route between the different stages of the user journey.

```tsx
// This is the primary pattern you must follow.
export function FormView() {
  const { context, actions } = runtime;

  switch (context.status) {
    case 'idle':
      return <IntroScreen onStart={actions.start} ... />;
    case 'filling':
      return <QuestionScreen />;
    case 'completed':
      return <CompletionScreen onRestart={actions.reset} ... />;
    case 'submitting':
      return <LoadingScreen />;
    case 'error':
      return <ErrorScreen onRetry={actions.submit} />;
    default:
      return null;
  }
}
```

REQUIRED — Completion behavior

- When `context.status === 'completed'`, the UI MUST render a dedicated completion/thank‑you view and MUST NOT render the form controls anymore.
- The completion view can be a simple message card or a full‑page screen, but it should clearly indicate success and provide an optional action (e.g., `Restart` via `actions.reset()` and then `actions.start()`).
- Do not leave the user on the last step with inputs visible after a successful `actions.submit()`; swap the view immediately on status change.
- Stories generated for documentation and testing MUST implement this behavior (acceptance criteria).

### Pattern 1: Typeform‑style (full‑page)

This mode shows one question at a time in a full‑page, keyboard‑centric flow. Compose the high‑level layout and inputs from `@formlink/ui` exactly as below.

Required components (Option A — using `@formlink/ui/components`):

```ts
import {
  TypeFormLayout,
  TypeFormProgress,
  TypeFormQuestionHeader,
  TypeFormContinueFooter,
  TypeFormNavigation,
  TypeFormTransition,
} from "@formlink/ui/components";

import { TypeFormTextInput, UnifiedDropdownSelect } from "@formlink/ui";
```

Required components (Option B — using `@formlink/runtime/ui/react`):

```ts
import {
  TypeFormLayout,
  TypeFormProgress,
  TypeFormQuestionHeader,
  TypeFormContinueFooter,
  TypeFormNavigation,
  TypeFormTransition,
  // Inline primitives are also available
  InlineSelect,
  InlineRating,
  InlineRanking,
} from "@formlink/runtime/ui/react";
```

Composition:

- Shell: Wrap the entire step view with `TypeFormLayout`.
- Top bar + progress: Render a simple top bar (brand/space) and `TypeFormProgress` using `context.progress`.
- Step body: Wrap the current question in `TypeFormTransition questionId={context.currentId!}`.
  - Add `TypeFormQuestionHeader` with `question` and `questionNumber={progress.index + 1}`.
  - Render exactly one input control (Typeform primitives).
  - Show validation error via `context.get.visibleError(qId)` under the control.
- Desktop continue strip: Add `TypeFormContinueFooter` under the input (no back button). It is hidden on mobile.
- Floating navigation: Always render `TypeFormNavigation` outside the layout; it provides the mobile bottom bar and desktop floating up/down arrows.

Behavior:

- Continue: validate current step; if valid and not last step call `actions.next()`; if last step call `actions.submit()`.
- Use `context.get.visibleError(qId)` for error display. Errors are revealed on first failed validate and cleared on change when valid.

Navigation hooks:

- The UI package exports two hooks to wire up the canonical Typeform interactions:
  - `useTypeFormScroll({ onNext, onPrevious, enabled })`: Captures wheel scroll to navigate between steps. Allows native scroll within elements that include `data-allow-scroll`.
  - `useTypeFormSwipe({ onNext, onPrevious, enabled })`: Captures vertical touch swipes to navigate on mobile.
- Keyboard handling (Enter, arrow keys) is handled by the input primitives and the Continue footer; a dedicated keyboard hook is optional and app-specific.

Example wiring:

```tsx
import { useTypeFormScroll, useTypeFormSwipe } from '@formlink/ui';

function TypeformNavWiring({ onNext, onPrevious }: { onNext: () => void; onPrevious: () => void }) {
  useTypeFormScroll({ onNext, onPrevious, enabled: true });
  useTypeFormSwipe({ onNext, onPrevious, enabled: true });
  return null;
}

// Inside your Typeform view render tree
<TypeFormLayout>
  {/* ...progress + step... */}
</TypeFormLayout>
<TypeformNavWiring onNext={handleContinue} onPrevious={() => runtime.actions.prev()} />
```

Note: If you render scrollable content inside a step (e.g., long descriptions), add `data-allow-scroll` to that container to allow native scrolling without triggering navigation.

Choice rendering rules (Typeform):

- Single choice:
  - If options.length is 1–5: render a Typeform list using `TypeFormSelect` (click/Enter to advance).
  - If options.length ≥ 6: render a searchable dropdown using `UnifiedDropdownSelect` with `mode="typeform"`.
- Multiple choice:
  - If options.length is 1–5: render a compact checklist using `UnifiedMultiSelect` with `mode="typeform"` (no dropdown chrome).
  - If options.length ≥ 6: render a searchable dropdown multi-select using `UnifiedDropdownMultiSelect` with `mode="typeform"`.
  - Auto‑advance only when the control reports a definite selection (non‑empty), otherwise require Continue.

Multiple choice example:

```tsx
import { UnifiedMultiSelect, UnifiedDropdownMultiSelect } from "@formlink/ui";

function MultipleChoiceStep({
  q,
  value,
  handleContinue,
}: {
  q: any;
  value: unknown;
  handleContinue: () => void;
}) {
  const raw = (q.type as any)?.options ?? [];
  const options = raw.map((o: any) => ({ value: o.value, label: o.label }));

  // Normalize value → string[]
  const valArr: string[] = Array.isArray(value)
    ? (value as string[])
    : typeof value === "string"
      ? (() => {
          try {
            const arr = JSON.parse(value);
            return Array.isArray(arr) ? arr : [];
          } catch {
            return [];
          }
        })()
      : [];

  if (options.length > 0 && options.length < 6) {
    // Short list: inline checklist, no dropdown chrome
    return (
      <UnifiedMultiSelect
        mode="typeform"
        options={options}
        value={valArr}
        onChange={(arr) => runtime.actions.set(q.id, arr)}
        onSubmit={handleContinue}
      />
    );
  }

  // Long list: searchable dropdown multi-select
  return (
    <UnifiedDropdownMultiSelect
      mode="typeform"
      options={options}
      value={valArr}
      onChange={(arr) => runtime.actions.set(q.id, arr)}
      onSubmit={handleContinue}
    />
  );
}
```

### Pattern 2: Classic-style

This mode shows multiple questions at once.

- Use a plain `<form>` element with an `onSubmit` handler that calls `actions.validateAll()` and `actions.submit()`.
- Loop over `context.visibleIds` to render each question.
- Use `AnimatePresence` and `motion.div` to animate questions that appear/disappear due to branching.
- **RULE: DO NOT USE `react-hook-form`.** The runtime is the only state manager.

Field layout (shadcn Field)

- Wrap each control with the Field primitives from `@formlink/ui`:
  - `Field` (outer wrapper)
  - `Label` (question title)
  - `FieldDescription` (optional help text)
  - `FieldControl` (the actual input component)
  - `FieldMessage` (first visible validation error)
- Error resolution MUST use `context.get.visibleError(qId)` so messages only appear after the first failed validate and clear when the value becomes valid.

Example (Classic section)

```tsx
import {
  Input,
  Label,
  Field,
  FieldControl,
  FieldDescription,
  FieldMessage,
  Button,
} from "@formlink/ui";

function ClassicSection() {
  const snap = runtime.context.getSnapshot();
  const ids = snap.visibleIds;

  return (
    <form
      onSubmit={async (e) => {
        e.preventDefault();
        const res = await runtime.actions.validateAll();
        if (res.isValid) await runtime.actions.submit();
      }}
      className="space-y-6"
    >
      {ids.map((qId) => {
        const q = runtime.context.get.q(qId);
        const err = runtime.context.get.visibleError(qId);
        return (
          <Field key={qId}>
            <Label htmlFor={qId} className="text-base font-medium">
              {q.title}
            </Label>
            {q.description ? (
              <FieldDescription>{q.description}</FieldDescription>
            ) : null}
            <FieldControl>
              {/* Choose the correct input by q.type.name; this example shows text */}
              <Input
                id={qId}
                value={String(runtime.context.get.value(qId) ?? "")}
                onChange={(e) => runtime.actions.set(qId, e.target.value)}
              />
            </FieldControl>
            <FieldMessage>{err}</FieldMessage>
          </Field>
        );
      })}
      <div className="pt-2">
        <Button type="submit">Submit</Button>
      </div>
    </form>
  );
}
```

### Pattern 3: Chat-style

- Use the `useChatRuntime` hook from `@formlink/runtime/chat`.

## 6. High-Quality Baseline Templates

### File: FormView.tsx (Typeform)

```tsx
'use client';
import React from 'react';
import { runtime } from './runtime';
import {
  TypeFormLayout,
  TypeFormQuestionHeader,
  TypeFormContinueFooter,
  StepTransition
  IntroScreen,
  CompletionScreen
} from '@formlink/ui/components';
import { TypeFormTextInput } from '@formlink/ui'; // and other inputs

function QuestionScreen() {
  const { context, actions } = runtime;
  const qId = context.currentId;
  const q = context.get.q(qId);
  if (!q) return null;

  const isValid = actions.validate(qId).isValid;
  const isSubmitting = context.status === 'submitting';

  return (
    <TypeFormLayout>
      <TypeFormTransition key={qId}>
        <TypeFormQuestionHeader
          question={q}
          questionNumber={context.progress.index + 1}
        />
        <div className="mt-8">
          <TypeFormTextInput
            value={String(context.get.value(qId) ?? '')}
            onChange={(v) => actions.set(qId, v)}
            onSubmit={() => !isSubmitting && isValid && actions.next()}
            disabled={isSubmitting}
          />
        </div>
        <TypeFormContinueFooter
          onClick={() => !isSubmitting && isValid && actions.next()}
          isLoading={isSubmitting}
          isValid={isValid}
          errorMessage={context.get.error(qId)}
        />
      </TypeFormTransition>
    </TypeFormLayout>
  );
}

export default function FormView() {
  const { context, actions } = runtime;

  switch (context.status) {
    case 'idle':
      return <IntroScreen form={context.form} onStart={actions.start} />;
    case 'filling':
    case 'submitting':
      return <QuestionScreen />;
    case 'completed':
      return <CompletionScreen onRestart={actions.reset} />;
    default:
      return <div>Loading...</div>;
  }
}
```

Rules for input groups

- Always place InputGroup inside FieldControl.
- Use InputGroupInput/InputGroupTextarea for the control; never nest native inputs inside buttons.
- Addons use align="inline-start" | "inline-end" | "block-start" | "block-end".
- For actions inside addons, prefer InputGroupButton.
- Ensure aria-invalid is set via FieldMessage visibility as appropriate; focus styles are wired to the control.

Signature capture & upload

- Schema: `name: 'signature'` stores a string value. Recommended to store the uploaded URL string (not a data URL) in the runtime value.
- UI: Use `InlineSignature` from `@formlink/runtime/ui/react`. It always renders a Clear button. It renders a Save button if you pass `onUpload`.

Example (Typeform pattern with Save button)

```tsx
import { InlineSignature } from "@formlink/runtime/ui/react";

function SignatureField({ qid }: { qid: string }) {
  const val = runtime.context.get.value<string | null>(qid) ?? null;
  return (
    <InlineSignature
      value={val}
      onChange={(s) => runtime.actions.set(qid, s)}
      onUpload={async (file) => {
        const desc = await runtime.actions.upload(qid, file);
        // Store URL string as the answer (schema for signature is string)
        runtime.actions.set(qid, desc.url);
      }}
    />
  );
}
```

Alternative (upload on Continue)

- You can omit `onUpload` and upload on Continue by converting the current data URL to a `File` and calling `runtime.actions.upload(qid, file)` before advancing. The `InlineSignature` component does not upload by itself unless `onUpload` is provided.

Helper (data URL → File)

```ts
function dataUrlToFile(
  dataUrl: string,
  filename = "signature.png",
): File | null {
  try {
    const parts = dataUrl.split(",");
    if (parts.length < 2) return null;
    const meta = parts[0] || "";
    const base64 = parts[1] || "";
    const mime = meta.match(/data:(.*?);base64/)?.[1] || "image/png";
    const binary = typeof atob === "function" ? atob(base64) : "";
    const len = binary.length;
    const bytes = new Uint8Array(len);
    for (let i = 0; i < len; i++) bytes[i] = binary.charCodeAt(i);
    return new File([bytes], filename, { type: mime });
  } catch {
    return null;
  }
}
```
