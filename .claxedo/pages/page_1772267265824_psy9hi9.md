### Core PTY (`packages/opencode/src/pty/index.ts`)

- Uses `bun-pty` library

- Creates/manages PTY sessions for both terminals and managed processes

- Exposed via `/pty` HTTP routes in opencode server

### Process Management (`packages/claxedo-app/src/opencode-patches/process/`)

- `process.ts` - Types (ProcessConfig, ManagedProcess, Status)

- `index.ts` - Implementation using opencode's PTY (`Pty.create`, `Pty.write`, etc.)

- `routes.ts` - HTTP API at `/process`

- MCP tools in `claxedo-mcp.ts`

### Terminal UI (`packages/claxedo-app/src/overrides/components/terminal-*`)

- `terminal.tsx` - Main component that:

1. **Creates PTY**: Calls `sdk.client.pty.create()` (HTTP POST /pty)

2. **Connects via WebSocket**: Opens WebSocket to `/pty/:ptyID/connect`

3. **Renders**: Uses xterm.js for terminal display

4. **Handles I/O**: Sends keyboard input via WS, receives terminal output via WS

- `terminal-connection.ts` - WebSocket utilities (reconnection, close handling)

- `terminal-stream.ts` - Stream buffering for terminal output

- `terminal-recovery.ts` - Snapshot/restore for terminal state

- `terminal-tui.ts` - TUI detection and filtering

## The Issue

Both process management and terminal creation:

1. Use the same technology (`bun-pty`)

2. Are tightly coupled to opencode core (`@/pty`)

3. Can't be easily shared or decoupled

## Solution

Extract PTY functionality into a shared package and have both process management and terminal use this shared package.
